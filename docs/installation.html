Avant de commencer

Installer AssetFlow ERP en local

Deux façons d'obtenir un environnement local qui convient : un pack tout-en-un (XAMPP) ou des conteneurs (Docker). Dans les deux cas, voici ce qui tourne derrière l'application.

ComposantVersion conseilléeRôle
Serveur webApacheSert l'application aux navigateurs
PHP8.2.xExécute le code d'Espo
Base de donnéesMariaDB / MySQLStocke toutes les données
Espo9.2.0Socle applicatif (rôles, équipes, PDF, notifications natives)
À savoir — AssetFlow n'est pas un logiciel séparé : c'est Espo 9.2.0, avec des entités, des formules et des modèles PDF ajoutés par-dessus. L'installer, c'est installer Espo puis charger les fichiers de personnalisation présents dans ce dépôt.
Installation — étape 1

Installer Espo

  1. Télécharger l'archive

    Récupérer Espo 9.2.0 depuis espocrm.com, ou utiliser directement l'image Docker officielle (voir la section Hébergement).

  2. Créer la base de données

    Créer une base et un utilisateur dédiés :

    -- dans phpMyAdmin ou le client MariaDB
CREATE DATABASE assetflowcrm_db CHARACTER SET utf8mb4;
CREATE USER 'assetflow'@'localhost' IDENTIFIED BY 'changeme';
GRANT ALL PRIVILEGES ON assetflowcrm_db.* TO 'assetflow'@'localhost';
FLUSH PRIVILEGES;

    Remplacez changeme par un mot de passe de votre choix.

    Important — une fois l'installation terminée, Espo enregistre ces identifiants dans data/config-internal.php (chemin type : C:\xampp\htdocs\AssetFlowCRM\data\config-internal.php sous Windows). Si vous changez le nom de la base, l'utilisateur ou le mot de passe après l'installation, pensez à mettre à jour ce fichier en conséquence — sinon l'application ne pourra plus se connecter à la base et affichera une erreur de connexion au démarrage.

  3. Donner les droits d'écriture

    Le serveur web doit pouvoir écrire dans data/, custom/, client/custom/ et log/ — sinon l'assistant d'installation bloque à l'étape des permissions.

  4. Lancer l'assistant web

    Ouvrir l'adresse du site dans un navigateur. L'assistant vérifie les prérequis, demande la connexion à la base, puis crée le compte administrateur.

  5. Régler la langue et le thème

    Dans Administration → Paramètres du système, passer la langue en français et installer l'extension Modern Theme si vous le souhaitez.

Installation — étape 2

Charger les personnalisations AssetFlow

Une fois Espo installé nu, il faut y ajouter les entités et automatisations propres au projet. Ces fichiers se trouvent dans ce dépôt (dossier custom/) et ne contiennent aucune donnée — seulement la structure de l'application.

  1. Copier les métadonnées personnalisées

    Placer les définitions d'entités (CProduct, CSoftware, CITRequest, CHRRequest, Computer, MiseADisposition) dans custom/Espo/Custom/Resources/metadata de votre installation Espo, puis vider le cache depuis Administration → Effacer le cache.

  2. Importer les rôles, équipes et layouts

    Recréer les rôles EMPLOYEE, IT Manager, HR Manager avec leurs permissions, et les équipes IT Team / HR Team (voir la page Utilisation pour le détail de chaque rôle).

  3. Ajouter les formules et l'API PHP

    Coller les formules de calcul (jours de congé, statut de licence) sur les entités concernées, et déposer le contrôleur personnalisé de rafraîchissement des licences.

  4. Importer les modèles PDF

    Créer les modèles dans Administration → Modèles PDF pour chaque type de document (demande d'équipement, attestations RH, congés, mise à disposition...).

  5. (Optionnel) Brancher le service de notification RH

    Déployer le petit service Django séparément, configurer un webhook sortant sur CHRRequest (événement afterCreate), et renseigner vos propres identifiants SMTP côté Django. Le détail complet est expliqué juste en dessous.

Sans ce service Django — l'application fonctionne normalement, seule la notification automatique par courriel à l'équipe RH ne partira pas.
Installation — étape 3 (optionnelle)

Comment fonctionne la notification RH

Quand un employé crée une demande RH, l'équipe RH reçoit automatiquement un courriel récapitulatif avec un lien direct vers le ticket. Quatre maillons interviennent, dans cet ordre :

  1. Espo déclenche un webhook sortant

    Dès qu'un enregistrement CHRRequest est créé (événement afterCreate), Espo envoie une requête POST contenant les données du ticket au format JSON vers une URL que vous configurez dans Administration → Webhooks.

  2. Un service Django reçoit la requête

    Le point d'entrée /espocrm-webhook/ (fonction espocrm_webhook dans webhooks/views.py) parse le JSON et vérifie d'abord que la connexion SMTP fonctionne avant d'aller plus loin.

  3. Django construit le courriel HTML

    La fonction build_email_html() extrait le nom de l'employé, le département, le type de demande et l'identifiant du ticket, puis les insère dans un gabarit HTML avec un lien de retour vers la fiche dans Espo.

  4. L'envoi part par Gmail (SMTP)

    send_mail() authentifie la connexion avec un compte Gmail et un mot de passe d'application, puis livre le courriel à la boîte de réception RH. C'est cette étape qui a besoin de vos propres identifiants.

Où changer l'adresse Gmail et le mot de passe

Tout se passe dans un seul fichier : espocrm_webhook/espocrm_webhook/settings.py. Repérez le bloc de configuration email en bas du fichier et remplacez les deux valeurs marquées ci-dessous :

# espocrm_webhook/espocrm_webhook/settings.py
EMAIL_BACKEND = 'django.core.mail.backends.smtp.EmailBackend'
EMAIL_HOST = 'smtp.gmail.com'
EMAIL_PORT = 587
EMAIL_USE_TLS = True
EMAIL_USE_SSL = False

#  ↓↓↓ à remplacer par votre propre adresse Gmail
EMAIL_HOST_USER = 'votre-adresse@gmail.com'

#  ↓↓↓ à remplacer par un mot de passe d'application (16 caractères), PAS votre mot de passe Gmail
EMAIL_HOST_PASSWORD = 'xxxx xxxx xxxx xxxx'

DEFAULT_FROM_EMAIL = 'votre-adresse@gmail.com'

Générer le mot de passe d'application Gmail

  1. Activer la validation en deux étapes

    Sur le compte Gmail qui enverra les courriels : myaccount.google.com → Sécurité → Validation en deux étapes. Un mot de passe d'application ne peut pas être généré sans ça.

  2. Créer le mot de passe d'application

    Toujours dans Sécurité, chercher Mots de passe des applications, choisir un nom (par exemple « AssetFlow webhook ») et générer. Google affiche une chaîne de 16 caractères une seule fois.

  3. Coller cette chaîne dans EMAIL_HOST_PASSWORD

    Copier-coller telle quelle, espaces compris ou non — les deux formats fonctionnent avec Django. Ce n'est jamais le mot de passe habituel du compte Gmail.

L'adresse est aussi codée en dur dans views.py

Changer settings.py ne suffit pas : l'adresse de la boîte RH est répétée telle quelle dans webhooks/views.py, à la fonction espocrm_webhook, dans l'appel send_mail() — une fois comme expéditeur, une fois comme destinataire.

# webhooks/views.py — dans espocrm_webhook()
send_mail(
    sujet,
    '',
    'votre-adresse@gmail.com',      <-- expéditeur, à remplacer
    ['votre-adresse@gmail.com'],    <-- destinataire(s), à remplacer
    fail_silently=False,
    html_message=message,
)

Le plus sûr est de ne pas répéter l'adresse une troisième fois ici : réutilisez la valeur déjà définie dans settings.py plutôt que de la retaper.

# en haut de webhooks/views.py
from django.conf import settings

/* ... puis dans send_mail() ... */
send_mail(
    sujet,
    '',
    settings.DEFAULT_FROM_EMAIL,
    [settings.EMAIL_HOST_USER],   <-- ou une liste de destinataires dédiée
    fail_silently=False,
    html_message=message,
)

La même adresse réapparaît aussi dans build_email_html() (variables ticket_link et site_link), mais là il s'agit du nom d'hôte de votre serveur AssetFlow, pas de Gmail — à adapter séparément avec votre propre domaine ou IP si vous reprenez ce code.

Adresse dédiée recommandée — créez un compte Gmail spécifique à cette intégration (par ex. une boîte partagée RH) plutôt que d'utiliser un compte personnel : plus facile à révoquer, à faire tourner, et à partager avec un successeur.
Ne jamais committer ces valeurs — EMAIL_HOST_USER et EMAIL_HOST_PASSWORD ne doivent pas rester en clair dans settings.py si ce fichier part sur un dépôt Git, même privé. Chargez-les plutôt depuis une variable d'environnement, par exemple EMAIL_HOST_PASSWORD = os.environ.get('EMAIL_HOST_PASSWORD'), et gardez le fichier .env correspondant hors du dépôt (.gitignore). Si un mot de passe d'application a déjà été exposé (poussé sur GitHub, partagé dans un fichier, etc.), révoquez-le immédiatement dans les paramètres Gmail et générez-en un nouveau — le remplacer dans le code ne suffit pas, l'ancien reste valide tant qu'il n'est pas révoqué côté Google.
Hébergement

Le faire tourner en local

Pas besoin de serveur distant pour l'utiliser ou le démontrer : XAMPP suffit pour aller vite, Docker donne un environnement propre et jetable.

  1. Installer XAMPP

    Télécharger XAMPP (Apache + PHP + MariaDB + phpMyAdmin) depuis apachefriends.org et l'installer.

  2. Démarrer Apache et MySQL

    Ouvrir le panneau de contrôle XAMPP et démarrer les modules Apache et MySQL.

  3. Créer la base via phpMyAdmin

    Ouvrir http://localhost/phpmyadmin, créer une base assetflowcrm_db (utf8mb4). Par défaut, l'utilisateur root n'a pas de mot de passe.

  4. Déposer Espo dans htdocs

    Extraire l'archive Espo dans C:\xampp\htdocs\assetflow (Windows) ou /Applications/XAMPP/htdocs/assetflow (Mac), puis copier les fichiers de ce dépôt par-dessus.

  5. Lancer l'installation

    Ouvrir http://localhost/assetflow et suivre l'assistant : hôte localhost, base assetflowcrm_db, utilisateur root, mot de passe vide (ou celui que vous avez défini).

L'image officielle EspoCRM contient déjà PHP, Apache et l'application. Il ne manque qu'une base MariaDB à côté.

# docker-compose.yml
services:
  espocrm-db:
    image: mariadb:latest
    container_name: espocrm-db
    environment:
      MARIADB_ROOT_PASSWORD: changeme
      MARIADB_DATABASE: espocrm
      MARIADB_USER: espocrm
      MARIADB_PASSWORD: changeme
    volumes:
      - espocrm-db:/var/lib/mysql
    restart: always

  espocrm:
    image: espocrm/espocrm
    container_name: espocrm
    environment:
      ESPOCRM_DATABASE_PLATFORM: Mysql
      ESPOCRM_DATABASE_HOST: espocrm-db
      ESPOCRM_DATABASE_USER: espocrm
      ESPOCRM_DATABASE_PASSWORD: changeme
      ESPOCRM_ADMIN_USERNAME: admin
      ESPOCRM_ADMIN_PASSWORD: changeme
      ESPOCRM_SITE_URL: "http://localhost:8080"
    volumes:
      - espocrm:/var/www/html
    restart: always
    depends_on:
      - espocrm-db
    ports:
      - 8080:80

volumes:
  espocrm-db:
  espocrm:
docker compose up -d

Une fois les conteneurs démarrés, ouvrir http://localhost:8080, puis copier les fichiers de personnalisation de ce dépôt dans le volume espocrm — le compte admin est créé automatiquement avec les identifiants indiqués ci-dessus (à changer avant tout usage réel).

Après l'installation — dans les deux cas, il reste à charger les personnalisations AssetFlow (étape précédente) : entités, formules, rôles et modèles PDF ne viennent pas avec Espo de base.

Rendre l'application accessible depuis internet

Par défaut, l'application n'est accessible que depuis votre propre réseau local. C'est suffisant pour tester ou faire une démo. Si vous voulez y accéder depuis l'extérieur (par exemple pour la montrer à distance), voici le principe général — à adapter avec vos propres valeurs, aucune ici n'est réelle.

1. Le problème de l'adresse IP qui change

La plupart des connexions internet grand public ont une adresse IP publique dynamique : elle peut changer après un redémarrage du routeur. Un DNS dynamique (DDNS) résout ce problème en associant un nom fixe (par exemple monprojet.exemple-ddns.net) à votre adresse IP actuelle, mise à jour automatiquement. Des services comme No-IP, DuckDNS ou Dynu proposent cela gratuitement.

2. La redirection de port sur le routeur

Le DDNS fait pointer un nom vers votre routeur, mais ne donne pas accès à l'application elle-même. Il faut en plus configurer une redirection de port (souvent appelée port forwarding) dans l'interface d'administration du routeur, pour transmettre les connexions reçues vers la machine qui héberge Espo :

ParamètreExemple (à remplacer)
Port externe8080
Adresse IP locale du serveur192.168.1.50
Port interne (celui d'Espo)80
ProtocoleTCP

Ces valeurs sont propres à chaque installation (votre box/routeur, votre réseau local). L'interface exacte varie selon le fabricant du routeur.

3. Sécuriser l'accès distant

  • Mettre HTTPS en place (certificat via un reverse proxy comme Nginx/Caddy, ou Let's Encrypt) plutôt que du HTTP en clair
  • Changer tous les mots de passe par défaut avant toute exposition publique
  • Limiter les tentatives de connexion et surveiller les journaux d'accès
  • Envisager un VPN plutôt qu'une exposition directe si l'accès distant n'est pas permanent
Recommandation — pour découvrir ou faire évoluer le projet, l'accès local (XAMPP ou Docker) suffit largement. L'exposition publique n'est utile que si vous devez réellement y accéder depuis l'extérieur, et mérite d'être bien sécurisée avant.
