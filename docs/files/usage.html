Rôles, permissions et entités

AssetFlow repose sur le système de comptes, rôles et équipes natif d'Espo : chaque personne a un compte individuel — pas de compte partagé — et voit uniquement les modules autorisés par son rôle.

  1. Se connecter

    Ouvrir l'adresse de l'application, saisir son identifiant et son mot de passe.

  2. Changer le mot de passe temporaire

    À la première connexion, remplacer le mot de passe fourni par l'administrateur.

  3. Retrouver son espace

    Le menu affiche uniquement les modules autorisés par le rôle du compte.

Fonctionnement

Ce que chaque rôle peut faire

EMPLOYEE

Employé

  • Créer une demande IT ou RH
  • Suivre l'état de ses propres demandes
  • Ne voit ni l'inventaire ni les comptes des autres
IT MANAGER

Responsable IT

  • Gérer équipements, ordinateurs, logiciels et licences
  • Traiter les demandes IT
  • Enregistrer une mise à disposition
  • Actualiser les statuts de licence
HR MANAGER

Responsable RH

  • Traiter les demandes RH (accepter / refuser / reporter)
  • Générer le document PDF correspondant
  • Ne voit pas les modules techniques
ADMIN

Administrateur

  • Créer et désactiver des comptes
  • Configurer rôles, équipes et permissions
  • Accès complet à tous les modules

Modélisation

Les entités de l'application

Six entités personnalisées, plus les entités natives d'Espo. Clique sur une entité pour voir ses champs.

CHAMPS CLÉS
  • name, type, categoryId
  • quantity, status
DÉTAILS
  • Catégories : câbles, matériel informatique, périphériques, mobilier
  • Géré par le responsable IT / admin
CHAMPS CLÉS
  • name, type, quantity, purchasePrice
  • licenseExpiry, daysRemaining, licenseStatus
DÉTAILS
  • Statuts : actif, bientôt expiré, expiré, sans échéance
  • Recalcul via le bouton "Refresh Licenses"
CHAMPS CLÉS
  • computerName, serialNumber, assetType
  • condition, status
DÉTAILS
  • Distinct du stock générique (CProduct)
  • Lié aux licences logicielles et aux clés Windows
CHAMPS CLÉS
  • fullName, position, managerFullName
  • productName, priority, status
DÉTAILS
  • Statuts : pending, Processing, accepted, rejected
  • Créée par l'employé, décidée par le resp. IT
CHAMPS CLÉS
  • requestType, subRequestType, department
  • startDate, endDate, decision, pdfTemplateId
DÉTAILS
  • 4 familles : congés, administratif, recrutement, santé
  • Le formulaire s'adapte au type choisi
CHAMPS CLÉS
  • fullName, brand, model, ram, serialNumber
  • processor, accessories
DÉTAILS
  • Produit un PDF de remise de matériel
  • Réservée aux profils techniques
CHAMPS CLÉS
  • username, isActive, roles, teams
DÉTAILS
  • Le rôle définit les actions possibles, l'équipe le périmètre partagé
  • Géré uniquement par l'administrateur
